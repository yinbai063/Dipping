# Dipping Monitor（通道录像）

独立程序，**不并入 NCM Monitor**。主界面与窗口标题为 **「Dipping Monitor」**。左右两台与 NCM 同型号的海康 SCMVS 智能相机，Live 下录一段 dipping 视频，供人眼检查 10 个通道。二期再自动判断堵塞。

**工程目录：** `E:\yb2\软件开发\Dipping`  
**最近 commit：** `9040208` — 连拍中可点「停止连拍」（`c93a897`）、README 一期/二期说明。  
**不要和正在跑的 NCM、官方 SCMVS 同时登录同一台相机。** 默认 IP：左 `192.168.2.50`、右 `192.168.2.51`（NCM 产线相机是 `.100` / `.101`）。

**应用图标：** `Dipping.WPF/Assets/app.ico`（绿底白字 YB，多尺寸 ICO；`ApplicationIcon` + 各窗口 `Icon="/Assets/app.ico"`）。

一期录像与 TCP 触发已按当前约定实现。关程序须用窗口关闭（不要用 VS「停止调试」），以便写回相机触发并停跑。

- 登录不改相机已有触发/运行模式。Live 临时改为内部触发连续取流；**停预览 / 登出 / 关闭程序**时写回登录时记下的 TriggerMode、TriggerSource，并 `StopRun`（不再 StartRun，避免机身灯一直亮）

- 主界面：**配置**、**相机监控**（`Show`，不锁主窗）。监控默认约 980×644；关监控窗不登出
- TCP 始终监听（不依赖是否勾选自动录像）。左 `REC_START_DIPPING_L`，右 `REC_START_DIPPING_R`
- 片子先写本地目录，再复制共享 UNC（空则不复制）
- 通道框/分析接口已留；监控右侧通道表已去掉。主界面 10 通道表一期显示「—」
- Live 超过约 5 秒无新图：红字「相机未更新图像，请检查相机及其接线」。不自动登出、不自动重连
- 监控按钮：可点蓝、不可点浅灰、登录/Live 绿、录像中「停止录像」红、连拍中「停止连拍」橙（与「录像/停止录像」不同，连拍是 **单钮切换**）

### 二期通堵设计（草案，2026-10）

**当前阶段：** 一期录像与接口已够用；**不必改 Dipping 代码**，先按本文档与离线工具试算法。正式实现时再写入 `IChannelAnalyzer`。

#### 成像与场景

- **NCM、Dipping 均为黑白/灰度** 智能相机画面（不是彩色）。
- 画面中部为一排 **10 根 tube 通道**（竖直金属管/喷嘴，尖端朝下）。
- 管间距小；**滴水时液滴可大于管口直径**，会 **遮挡邻近通道** 的部分视野。
- **越靠里（通常画面右侧/深处）越暗**；左侧易过曝。需 **分通道** 处理，不能全图一套阈值。

#### 工艺含义（通 / 堵）

| 状态 | 含义 |
|------|------|
| **通（未堵）** | 该通道在 **应滴水的时间窗内** 出现 **滴水过程**（挂滴、滴落、帧间变化等） |
| **堵（异常）** | 该通道在 **应滴水的时间窗内** **始终没有** 滴水过程 |
| **滴水前无水滴** | **基准态**，用于建背景；**不能** 当作「堵」 |

「无水滴截图」= 滴水开始前；「有水滴截图」= 滴水过程中某一时刻。**判堵只看判定窗，不看基准窗。**

#### 时间窗（一次 dipping）

1. **基准窗** — 滴水开始前：只算各 ROI 背景（median 等），**不出通堵结论**。
2. **判定窗** — 应出现滴水过程：每通道有滴水特征 → **通**；全程无 → **堵**。
3. **收尾窗**（可选）— 滴停后稳定态；一般 **不作为** 判堵主依据。

正式输入仍为一期 **MJPEG AVI（约 3 秒）**；帧率与 Live 一致。开发期可用连续 JPG 序列（见下「测试数据」）先讨论参数。

#### ROI 与邻道串扰

- 每通道 **竖条 ROI**，以 **管出口中心** 为轴，**宁窄勿宽**（与 `Dipping_PythonTool` 一致）。
- 判据重点：**管尖正下方一小段**（挂滴/滴落），少包含邻管区域。
- **归属**：变化区域水平中心须落在本通道列内；跨列时按 **更靠近哪根管中心** 分配，或标 **低置信度**。
- **时序优先于单帧**：邻道挂滴在本 ROI 边缘出现，但 **本列下方** 无持续帧间变化 → 不判本通道通。

#### 算法方向（规则 + 时序，暂不依赖深度学习）

每通道、在 **判定窗** 内可考虑（实现时在 `Dipping_PythonTool` 试，再迁入 `IChannelAnalyzer`）：

- 相对 **基准窗** 的帧间差分 / 时序方差；
- ROI 下半段暗连通域（挂滴）与 **高光点**（液滴镜面反射）；
- 规则示例：判定窗内 **≥ K 帧** 满足「滴水特征」→ 通；否则 → 堵。

**暗区（约 8～10 路）：** 每通道独立基准与阈值；ROI 内 CLAHE/局部对比；暗区 SNR 低时可 **低置信度** 或「待确认」（是否要上 UI 待定）。

#### 测试数据（现场连拍 JPG）

路径（示例）：

`E:\yb2\测试数据记录\Diping ai  camera test照片\AI Camera Dipping test_挑出来测试用`

- 约 **74 张** 同视角连续 JPG（文件名序号约 `221`～`310`），管排在 **全幅中上部**；末尾 2 张为管排 **位置截图**。
- 文件名中 `_NG!` 为相机/方案输出标记，**不等于** Dipping 通堵标签。
- **用途：** 划分基准窗/判定窗、试 ROI 位置、讨论分通道阈值；**不能替代** 正式 **Dipping AVI** 验收（压缩、帧率、触发时刻与产线一致）。
- **手持晃动：** 若连拍时 **相机未固定、画面整体在动**，则 **同一套像素 ROI 不能贯穿整段序列**——整幅平移/抖动会被帧差当成「全图都在变」，通堵时序试跑 **结果不可信**。这类 JPG 仍适合：**单张或挑几帧最稳的** 看滴水长什么样、管排大致在哪；**正式标 ROI + 跑 analyze** 请用 **Dipping 固定安装 + 录像 AVI**。
- **缺口：** 需补 **已知堵路** 的连拍或 AVI；`labels.csv` 需人眼标十路通堵。

离线工具用法见：`E:\yb2\软件开发\Python 程序开发\Dipping_PythonTool\README.md`（含 JPG 序列转 AVI 做试跑）。

#### 实现顺序建议

1. 用测试 JPG 或正式 AVI 标定 `rois.json`（左/右各一套）。
2. 在 `Dipping_PythonTool` 调通 **基准窗 + 判定窗 + 分通道时序规则**，与 `labels.csv` 对比。
3. 规则稳定后写入 `IChannelAnalyzer`，WPF 十路表与监控叠框。

## 运行

```powershell
dotnet build Dipping.sln
```

输出：`Dipping.WPF\bin\Debug\net8.0-windows\Dipping.exe`  
发布配置：`Dipping.WPF/Properties/PublishProfiles/FolderProfile.pubxml`（自包含单文件 x64；`PublishDir` 可按本机修改）

**VS2022：** 打开 `Dipping.sln`，启动项目设为 **Dipping.WPF**，再 F5。不要对 `Dipping.Core` 按 F5。

1. 关闭官方 SCMVS，也关闭占用同一相机的 NCM  
2. 主界面点 **相机监控**（启动已搜相机，窗内可再点 **查找相机**）  
3. 左右各自登录。关监控窗不登出；关 Dipping 主程序才登出并恢复相机  
4. 未勾选 **自动录像** 时点「录像」只录这一台；到时或「停止录像」后回到 Live  
5. **拍照 / 连拍** 按配置保存  
6. 录像路径：`本地根目录\yyyyMMdd_HHmmss\左相机.avi`（及右相机）  
7. 配置了共享目录则收尾整夹复制  

### PC 程序开录（TCP，默认端口 10100）

连接后发**一行**（须带行尾）：

```
REC_START_DIPPING_L
REC_START_DIPPING_R
```

- 左右完全独立，各算各的时段次数  
- 认出指令后**立刻**回 `OK`（表示收下，不是录完）。未登录、未勾自动录像、不在时段、次数用尽时仍可能已回 OK，但不开录  
- `OK` 的行尾与指令相同：对方 `\r` 则 `OK\r`，`\n` 则 `OK\n`，`\r\n` 则 `OK\r\n`  
- 编码跟指令：UTF-8/ASCII 或 UTF-16 LE/BE  
- 旧指令 `REC_START_DIPPING`（无 `_L`/`_R`）不开录、不回 OK  
- 连接保持，可反复发。上位机不必心跳  
- 关 Dipping 后须在调试助手里**断开再连接**；界面有时仍显示已连接，旧套接字到不了新进程  

### 按时段和次数限制

配置里「自动录像时按时段和次数限制」，**默认不勾选**（不限制）。勾选后：

- 每天 12 个两小时时段（从 07:00 起），每行：序号、启用、时间段、次数  
- 默认表：只启用 07:00–09:00、次数 1；其余行可改、可勾  
- 到点**不会**自动开录，必须收到 `_L`/`_R`  
- 不在启用时段或该相机该时段次数用尽：忽略指令  
- 次数按相机分开，记在 `Data/record-schedule-usage.json`（不是 `config.json`）。按 07:00 到次日 07:00 算一天。删该文件即清当天次数，程序会在下次成功开录时再建  
- 配置表必须点 **保存** 才对正在跑的程序生效；不保存关窗即丢草稿  
- 手动录像不受此表限制

## 配置（config.json / 配置窗口）

配置窗打开高度约 576，输入框较矮；内容超出可滚动。保存才写入 `config.json`。

| 项 | 含义 |
|----|------|
| 左/右 IP | dipping 工位相机 |
| 账号密码 | 监控里左右各自登录，默认 `Admin` / `Abc1234` |
| 录像时长(秒) | 一次 dipping，默认 3 |
| 录像保存目录 | 空 = `Data\Videos` |
| 共享目录 | UNC，空 = 不复制 |
| 存图目录 | 拍照/连拍，空 = `Data\Images` |
| 连拍张数 / 上限 / 间隔 / 最快 | 与 NCM 连拍类似 |
| 自动录像 | 监控里左右各自勾选 |
| 自动信号源 | `PcProgram` 或 `Plc`（PLC 一期不真开录） |
| TCP 端口 | 默认 10100 |
| 自动录像时按时段和次数限制 | 总开关，默认关 |
| 时段表 | 12 行，不勾选总开关时仍可编辑 |

帧率等于 Live 实际出图。智能相机 `GetResultData` 没有工业相机裸流。
